    Partitions

    Since we are using SLURM on mechthild for job management the terminology changed. The formerly known queues are now called partitions. The partition should be selected to match the requirements of the job.

    To select a partition (queue) for your job use the -p ( or --partition=) parameter of the slurm submission tools srun/sbatch/salloc. Using the medium queue will be done by:

    srun -p medium <your other arguments>

    or 

    salloc -p medium <your other arguments>

    or 

    sinteractive -p medium <your other arguments>

    for interactive jobs.

    In case of a batch job, specify the following in your job file:

    #SBATCH --partition=medium

    Available Partition

    Name time limit Description
    long Infinity but default runtime is 2 hours Partition for long jobs. Please use this queue only when you need it. If you only want to try something please use medium or short. Interactive jobs will not work on this partition. This partition includes all non-GPU nodes. The estimated runtime can be set using the --time option.
    medium 1 day Partition for jobs with a medium runtime. It can be used with batch and interactive jobs. This partition includes all non-GPU nodes.
    short 2h Partition for short jobs. It can be used with batch and interactive jobs. It is the default queue. This partition includes all non-GPU nodes.
    gpu Infinity but default runtime is 2 hours Queue for GPU jobs. Please use this queue only when you need GPU support for your application. In contrast to the short and medium partition the time limit can be increased using the --time parameter during the job submission or in the batch file. If no time is specified the job cancels after two hours.

    Partitions vs. Node Types

    Note that the node types in the partitions are not unique. For example, all non-GPU nodes include standard and big-memory nodes. One can use feature constraints to restrict to a single node type. See the Requestable Features section on the Jobs page for details
