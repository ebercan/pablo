    Software

    Here is an overview of Software installed on mechthild. If you need more details about the runtime settings of a software package, type module help <modulename> on any node of mechthild. If some software is not available please feel free to contact the admin and ask for it. Some modules depend on each other so if you need a module whose dependencies are not fulfilled, take are loaded automatically.

    Software and Libraries installed on Mechthild

    A complete overview about the installed software is available using module avail. Some highlights are:

    • GNU Compiler Collection 6.5, 11, 13
    • Intel OneAPI Compiler 2025.0
    • AMD AOCC 5.0
    • CUDA 12.6.2
    • MATLAB up to 2024b
    • GNU Octave up to version 9
    • GROMACS
    • OpenMPI, MPICH

    Modules

    The installed software is managed using Lmod https://github.com/TACC/Lmod. This allows to switch easily between various software environments without big problems. Modules can be easily loaded, unloaded, etc. If a module is in incompatible to another one, the load can be canceled. In the next sections the basic commands will be explained.

    Changes from TCL Modules to LMOD

    Due to the switch from TCL (Environment) Modules to Lua Modules (LMOD), some smal changes appear. Frist, it is no longer necessary to load the modules command in your batch jobs. I.e., the line 

    source /etc/profile.d/modules.sh

    have to be removed from your jobfiles.

    Second, the names of the modules changed in order to obtain a more user friendly and intuiteve order. For this reason check 

    module avail

    for the correct names.

    load

    To select a module you have to load it using module load <Path of the Module>. Many developemnt modules depend on the previously loaded compiler. Some modules are only available for specific compilers. If the module is not available for the compiler loaded, an error will appear. The load command also checks if some modules conflict and tries to solve the problem automatically. If this is not possible an error is shown.

    It no compiler is loaded, it is assumed that GCC 11.4.1 is used, which is the system's default compiler. Although this compiler has a module, it is not required to be loaded.

    Example 1 (load compiler and some libraries): 

    module load compiler/gcc
module load cmake
module load openblas

    Troubleshooting

    Module Cache

    LMod uses a cache to accelerate finding modules. If this cache is outdated, for example when new modules got added, one can remove the cache via shell rm -rf ~/.cache/lmod/
