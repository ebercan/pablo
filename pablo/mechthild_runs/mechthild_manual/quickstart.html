    mechthild Quick Start Guide

    Welcome to mechthild, the Compute Cluster of our institute. With this guide you will be able to run your first job in a few minutes.

    Introduction

    mechthild is a parallel compute cluster comprising 82 compute nodes. Among these, 60 are general-purpose nodes, each equipped with two Intel Xeon Skylake 4110 CPUs. The remaining 22 nodes are GPU-enabled. For more details, please refer to the Hardware section.

    Each compute node is equipped with a minimum of 192GB of main memory. The interconnect between the nodes is facilitated by Intel's OmniPATH technology.

    The central storage system provides up to 128 TB using BeeGFS.

    For a complete description of the hardware see Hardware.

    Getting access mechthild

    mechthild can be used by all members of the Institute and the IMPRS. However, every user who wants to get access mechthild needs a confirmation from his group leader. The application form can be downloaded from here.

    Login mechthild

    mechthild can be reached from all computers inside the institute or if you have a VPN connection to the institute. A direct access from outside or from eduroam is not possible. In these cases, either connect to linssh.mpi-magdeburg.mpg.de first or use the VPN.

    To login mechthild simply connect via ssh to mechthild:

     ssh mechthild

    or 

    ssh mechthild.mpi-magdeburg.mpg.de

    If you plan to use graphical applications you have to connect with X11 support (UI support): 

    ssh -X mechthild

    This master node mechthild can be used to compile your software and to submit jobs. It is forbidden to run your programs directly on this node.

    Since the redesign of the system in November 2024, all nodes can be used to compile software. This is no longer restricted to the login nodes.

    Setup password free authentication

    Because the communication between the login server and the compute servers is done via ssh, you might want to set up password free authentication. This is done by generating an ssh key pair on mechthild using shell [ -e ~/.ssh/id_rsa ] || ssh-keygen -tRSA Leave the password blank (press ''ENTER'' for every question) and copy the key 

    ssh-copy-id -i .ssh/id_rsa.pub mechthild

    Now everything is set up to connect to the compute nodes without entering the password every time. In the same way, you can use the same to get a password free connection from your desktop to mechthild. In this case, execute the same from your desktop computer.

    If you are using Windows, Putty is a possible replacement for the ssh client or use the builtin ssh command of the Windows command line.

    Using Software

    There are two types of software: Closed and open source. If you want to use open source software on the cluster, please compile it again on mechthild to get it working with our local setup. The Spack package manager provides a huge set of software, that could installed in your home directory. Using closed source software on the cluster can be critical because of missing libraries or other issues. There is a set of preinstalled software, such as libraries, compilers and some standard tools, available. An overview can be found here: Software.     Compiling a Parallel Application

    If you have the source code of your software and want to compile it on mechhtild you need to load a compiler and if necessary other libraries like OpenMPI, BLAS or what your software needs. We recommend the usage of the GNU GCC 11.4.1 compiler suite since this is the default compiler on the systems and is available without loading a module.

    As an example we use the following small MPI program which prints the hostname and the job id to the console. 

    #include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <mpi.h>
int main(int argc, char **argv){
    int pid, pnr;
    size_t hlen=127;
    char hostname[128];
    MPI_Init(&argc, &argv);
    if( gethostname(hostname, hlen)){
        fprintf(stderr, "error: gethostname\n");
        return -1;
    }
    MPI_Comm_rank(MPI_COMM_WORLD, &pid);
    MPI_Comm_size(MPI_COMM_WORLD, &pnr);
    printf("%s: process %d of %d\n", hostname, pid, pnr);
    MPI_Finalize();
    return 0;
}

    This example can be downloaded: mpi_hostnames.c

    The following command will add the GNU GCC compiler and OpenMPI to the environment

    module load mpi/openmpi/4.1.7

    Now you can compile the program with 

    mpicc -o mpi_hostnames mpi_hostnames.c

    Running (Parallel) Applications

    There are two different ways to start your programs mechthild. The first is an interactive session and the second one is a batch job. All other ways to start jobs are not allowed.

    Interactive Jobs

    The interactive session behaves like a normal terminal session on your linux pc. You get a shell on one of the compute nodes where you can start your programs by hand and you can interact with the program. This is for example necessary if you want to interactively debug a program. The maximum duration of an interactive session is two hours. After that the session is canceled automatically.

    To start an interactive session on one compute node type:

    sinteractive

    If you want to extend the runtime to one day use: 

    sinteractive -p medium

    If there are enough free resources, this will open a shell on a compute node.

    By default the ''short'' partition is used for interactive jobs. (Details: Partitions). By running 

    snteractive -N 2 -c 16

    you obtain 2 compute nodes with all 16 cores on each node for your job.

    Running 

     sinteractive -n 128

    will acquire 128 CPU cores on various nodes

    If you want to open an interactive session on a node with 384GB of RAM, you can use:

    sinteractive -C RAM384

    Now you can start your program (after changing to the right path) by running:

    mpirun ./mpi_hostnames

    This will start your parallel application. That's basically all.

    Remark: Using X blocks a lot of resources. Use a graphical output only if there is no alternative.

    Batch Jobs

    Batch jobs are non interactive jobs and the preferred way to run large computational jobs mechthild. That means these jobs will have to run without any interaction from the user. To submit a job to the batch system you have to create a job file with all options and commands you need for your application. Typically, this file looks like this: 

    #!/bin/bash
# Your job name.
#SBATCH -J MPI_TEST
#
# Output files. .out. is for standard output .err. is for the error output. 
#SBATCH -o %x-%j.out-%N # name of the stdout, using the job name (%x), the job number (%j) and the first node (%N)
#SBATCH -e %x-%j.err-%N # name of the stderr, using the job name (%x), the job number (%j) and the first node (%N)
#
# Maximum expected runtime.  ( 00 Days, 1 hour, 00 minutes, 00 seconds) 
#SBATCH --time=00-1:00:00   
#
# Number of MPI Tasks
#SBATCH --ntasks=128 
#
# Choose Partition (Queue) 
#SBATCH --partition short 
#
# Mail Options 
#SBATCH --mail-type=FAIL,BEGIN,END    # An email is sent on begin, end, and failure of the job 
#SBATCH --mail-user=xxx@mpi-magdeburg.mpg.de   # E-Mail for notification
#
### END OF THE SLURM SPECIFIC PART ###


# load your modules 
module load mpi/openmpi/4.1.7

# run the application
mpirun ./mpi_hostnames

    All line beginning with # are comments, except of the lines with ''#SBATCH'' at the beginning. These are options for slurm to control the job creation. Saving this script as job.sh, you can submit it to the batch system by invoking:

    sbatch job.sh

    To check the status of your job(s) you can use 

    squeue

    or 

    scontrol show job <jobid>

    If you want to delete a job you can type 

    scancel <jobid>

    After a job is finished you will find a file named your_job_name-<jobid>.out.<Firstnode> in the directory from where you started the program. This file contains all output to STDOUT and STDERR of your application.

    Advice: To check if your jobfile is correct, start an interactive job and type 

    bash job.sh

    This example job file is available under mpi_hostnames.job

    Note: If your program does not use MPI you can omit the mpirun and the mpi module.

    AFS absence mechthild / Accessing your data

    We do not provide access to the AFS filesystem on mechthild. You can access your files either via ssh, scp or sftp from everywhere you have access to mechthild. Futhermore, if you are using a Linux desktop (with at least Ubuntu 20.04) in the institute, mechthild's network filesystem becomes available at /net/mechthild-data/ and thus /net/mechthild-data/home/${USER} will guide you to your home directory.

    This allows direct access to your cluster files from your desktop computer. In case the /net/mechthild-data directory is not availble, try 

    cd /net/mechthild-data/

    from the commandline first.
