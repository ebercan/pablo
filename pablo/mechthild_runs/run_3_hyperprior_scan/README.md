# run_4 Hyperprior Scan

Cross-validates four hyper-prior configurations across two catalyst featurizations, two mean functions, two model classes, and two outcome transforms. Uses the same CV folds (135 per inner config) and result structure as the main featurization × kernel scan.

## Grid

| Axis | Values | Count |
|------|--------|-------|
| Hyperprior | `baseline` (σ=2.5), `tighter_ls` (σ=2.0), `wider_ls` (σ=3.0), `strong_reg` (dir=5.0) | 4 |
| Cat feat | `interpretable`, `grover` | 2 |
| Outcome transform | `raw`, `logit` | 2 |
| Model class | `st_y`, `lcm_cs` | 2 |
| Mean function | `constant`, `type_linear` | 2 |

**Fixed**: KS4, matern52, solvent=physical, base=structured, floor=0.1, noise α=3.

**Outer cells** (= workers): hyperprior × cat_feat = 8.
**Inner configs** per cell: outcome × model × mean = 8.
**Folds** per inner config: 135.
**Total GP fits**: 8 × 8 × 135 = 8 640.

## Hyperprior configs

All keep the lengthscale floor at 0.1 and noise prior at InverseGamma(α=3, β from data).

| Config | `ls_scale` (σ) | `dirichlet_conc` | Rationale |
|--------|---------------|-----------------|-----------|
| `baseline` | 2.5 | 2.0 | Current recommended (control) |
| `tighter_ls` | 2.0 | 2.0 | Best logit CRPSS in hyper_prior_scan, needs CV confirmation |
| `wider_ls` | 3.0 | 2.0 | Slightly wider, confirm equivalence to baseline |
| `strong_reg` | 2.5 | 5.0 | Stronger Dirichlet weight regularization |

## Usage

All commands run from repository root.

### 1) Generate inputs

```bash
python -m pablo.mechthild_runs.run_3_hyperprior_scan.generate_inputs
```

Writes `pablo/mechthild_runs/run_3_hyperprior_scan/data/inputs.json`.

### 2) Initialize queue

```bash
python -m pablo.mechthild_runs.run_3_hyperprior_scan.scheduler init
```

### 3) Local smoke test (one outer cell)

```bash
python -m pablo.mechthild_runs.run_3_hyperprior_scan.scheduler worker --single
```

### 4) Submit to Mechthild

```bash
python -m pablo.mechthild_runs.run_3_hyperprior_scan.submit_mechthild submit
```

Full sbatch script generated by `submit_mechthild.py`:

```bash
#!/bin/bash
#SBATCH -J hp_prior_scan
#SBATCH --array=1-8%8
#SBATCH --cpus-per-task=1
#SBATCH --mem=8G
#SBATCH --time=12:00:00
#SBATCH --partition=medium
#SBATCH --mail-type=FAIL
#SBATCH --mail-user=enisbaris@mpi-magdeburg.mpg.de
#SBATCH -o pablo/mechthild_runs/run_3_hyperprior_scan/data/logs/worker_%A_%a.out
#SBATCH -e pablo/mechthild_runs/run_3_hyperprior_scan/data/logs/worker_%A_%a.err

export PYTHONPATH="$(pwd):$PYTHONPATH"
export OMP_NUM_THREADS=1
export MKL_NUM_THREADS=1
export TORCH_NUM_THREADS=1

echo "[worker] task=$SLURM_ARRAY_TASK_ID node=$SLURMD_NODENAME $(date -Iseconds)"
python -m pablo.mechthild_runs.run_3_hyperprior_scan.scheduler worker
echo "[worker] task=$SLURM_ARRAY_TASK_ID done $(date -Iseconds)"
```

### 5) Monitor

```bash
python -m pablo.mechthild_runs.run_3_hyperprior_scan.scheduler status
python -m pablo.mechthild_runs.run_3_hyperprior_scan.scheduler submitted
```

### 6) Aggregate results

```bash
python -m pablo.mechthild_runs.run_3_hyperprior_scan.concat_results [--strict]
```

Writes `data/results/hp_scan_aggregate.parquet`.

## Descriptor fix, 18.09.2026

The `interpretable` half of this scan (4 of 8 outer cells) was computed against `xtb_homo_eV`, `xtb_lumo_eV` and `xtb_gap_eV` read at the unoptimised input geometry (see `featurization_and_kernel_scan/WORK-PACKAGE.md`, "Descriptor fixes, 18.09.2026"). The verdict is unaffected: on `grover` alone, `tighter_ls` gives median CRPSS 0.388 against 0.167 / 0.171 / 0.167 for `baseline` / `strong_reg` / `wider_ls`, and it also leads on the `interpretable` half (0.195 vs ≤ 0.160). Not re-run. This folder is `run_3`; the README title and the 03.06 report call it `run_4` — a known renumbering, left as is.
